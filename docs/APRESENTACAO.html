Parte 4 · CI/CD e governançaFluxo proposto

Validar em isolamento antes de promover

Branch → PR → compilar → executar e testar
em datasets isolados → revisão → main → release

Por que CI completo?

Com dez tabelas, é simples validar tudo. Falhas bloqueiam a promoção.

Slim CI, no futuro: executar mudanças, dependentes e testes; manter as demais dependências disponíveis.

Como governar?

Versionar código, testes e catálogo. Registrar grão, medidas, linhagem e responsável.

Identidade de CI sem escrita em produção; credenciais fora do Git; acesso mínimo.

GitHub Actions proposto · Pipeline e proteção de main ainda não implantados07 / 08
